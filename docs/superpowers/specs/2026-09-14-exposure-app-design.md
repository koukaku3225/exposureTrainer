# 暴露療法（エクスポージャー）回数管理アプリ 設計書

日付: 2026-09-14
状態: 確定（MVP範囲）

## 1. 目的

竜一さん本人が、エクスポージャー（暴露療法）を段階的に実践し、記録・振り返りできるアプリ。
目標設定コーチ（prototypeManagementTool）とは別のアプリとして作る。

ノウハウの出典: パレオな男のブログ・Q&A動画（[20_調査/2026-09-14_暴露療法ノウハウ_パレオな男.md](../../../20_調査/2026-09-14_暴露療法ノウハウ_パレオな男.md)）。

## 2. 利用形態

- **自分専用**。ログインなし。データはブラウザの localStorage に保存
- Next.js（目標設定コーチと同じ構成方針）。**MVPはサーバー不要**（AI課題生成を次フェーズに送ったため、APIキーを扱うルートが要らない）
- 将来クラウド同期を足す可能性を見て、全データに `id` と `updatedAt` を持たせておく（[[goal-coach-sync-design]] の教訓：空の同期で本番データを消さないための前提条件）

## 3. 継続のための5つの工夫（採用済み）

ユーザーとの壁打ちで、暴露療法アプリ特有の脱落理由（怖さそのものへの恐怖、初期離脱の多さ）を調査した上で決めた。優先度順:

1. **if-thenプランニング** — 「次にXが起きたらYをやる」を常に1枚のカードで見せる
2. **初回は必ず成功で終わる** — オンボーディングで難易度1の課題を1つだけやらせ、「できました」で終える
3. **難易度ガードレール** — 難易度8以上の段は初期状態でロック。「直近3回を不安3以下でクリアすると解放」
4. **進み方を対等な3択にする** — 実践記録後「次の段へ進む／もう少し続ける／今回はここでよかった」を同じ見た目で並べ、「進まない」を恥じない選択にする
5. **ストリークではなく積み上げ** — 連続日数表示はやめ、「累計◯回」「不安スコアの合計低下」という、下がらない数字だけを見せる

外的報酬（ポイント・ご褒美）は不採用ではなく採用（本人の明示指示）。

## 5. 画面構成（MVP）

案C「テーマ横断の一覧ホーム」を採用。

```
[テーマ一覧]（ホーム）
  └ テーマカードをタップ → [テーマの詳細]（今日の一歩＋道のり。旧デザインの Main 画面）
        ├ [段階表]（同テーマの全段一覧。旧 Ladder 画面）
        ├ [実践記録]（旧 Practice 画面。3択で終わる）
        └ [テーマ別振り返り]
[全体の振り返り]（積み上げ表示。旧 Review 画面を拡張）
[恐怖チェック]（質問14問 → 結果 → テーマ作成への導線）
[設定]
[初回オンボーディング]（2画面。初回起動時のみ）
```

ボトムナビは5項目：ホーム（テーマ一覧）／段階表（いま開いているテーマの段階表へのショートカット）／いどむ（実践記録）／振り返り／設定。
「いどむ」「段階表」は文脈上「いま選択中のテーマ」に対して働く。テーマを何も選んでいない状態でこれらのタブを踏んだら、テーマ一覧に戻す。

## 6. データモデル

```ts
type Theme = {
  id: string;
  name: string; // 例: "人前で話す"
  createdAt: string; // ISO
  updatedAt: string;
  ifThen: { trigger: string; action: string } | null;
  stages: Stage[];
};

type Stage = {
  id: string;
  level: number; // 難易度 0-10（同梱テンプレートは概ね1-10の範囲で並ぶ）
  name: string;
  status: 'todo' | 'now' | 'clear'; // 'now' はテーマ内で1つだけ
  order: number; // 表示順（= 難易度順と一致させる）
  clearRequirement: { count: number; maxAnxietyAfter: number }; // 既定 { count: 3, maxAnxietyAfter: 3 }
};

type Record = {
  id: string;
  themeId: string;
  stageId: string;
  isImagined: boolean; // 想像でやったか現実でやったか
  anxietyBefore: number; // 0-10
  anxietyAfter: number; // 0-10
  choice: 'advance' | 'repeat' | 'stop_here' | null; // 記録直後に選んだ3択
  createdAt: string;
};

type FearCheckResult = {
  id: string;
  answers: boolean[]; // 14問、true=はい
  createdAt: string;
};

type RewardSetting = {
  id: string;
  thresholdPt: number;
  label: string; // 例: "新しい服"
};

type Settings = {
  clearRequirement: { count: number; maxAnxietyAfter: number }; // テーマ作成時の既定値・全体設定
  guardrailThreshold: number; // 既定 8。これ以上の難易度は初期ロック
  points: number;
  rewards: RewardSetting[];
  onboardingCompleted: boolean;
};
```

localStorage キー: `exposure.themes` / `exposure.records` / `exposure.fearChecks` / `exposure.settings`（目標設定コーチの `gc.*` 命名を踏襲し `exposure.*` とする）。

### ガードレールの判定ロジック

ある段の `level >= settings.guardrailThreshold` のとき、その段は初期状態で `locked: true`（Stage型には persist しないが、テーマ詳細の描画時に毎回このロジックで再計算する派生値とする）。
解放条件: そのテーマの直近3件の Record（どの段のものでも可）が、すべて `anxietyAfter <= 3` を満たす。満たしたら、そのテーマの全段のロックを解く（テーマ単位で解放。段ごとの個別解放は不要 — シンプルさを優先）。
解除の「上限を外す」個人設定はMVPでは実装しない（次フェーズ）。

### 進級（3択）のロジック

実践記録の直後、その Record が `clearRequirement` を満たしたか（直近 `count` 件が `anxietyAfter <= maxAnxietyAfter`）を判定し、満たしていれば「次の段へ進む」をデフォルト選択にする（が、自動遷移はしない。必ずユーザーが3択のどれかを選んで確定する）。
- 「次の段へ進む」: いまの段を `clear` にし、次の段を `now` にする
- 「もう少しこの段を続ける」: 状態を変えない
- 「今回はここでよかった」: 状態を変えない（「次の段へ進む」との違いは記録上の意思表示のみ。将来の振り返りで「進めたのに止めた回数」を出せるようにするため、Record.choice に保存する）

## 7. 同梱テーマテンプレート

調査ファイル（[20_調査/2026-09-14_暴露療法ノウハウ_パレオな男.md](../../../20_調査/2026-09-14_暴露療法ノウハウ_パレオな男.md)）と恐怖の5分類をもとに、5テーマ分をあらかじめ用意する。各テーマ7〜9段、難易度順。

1. **人前で話す**（評判・失敗）— モックで使った段階表をそのまま採用
2. **恥（評判）** — 例: パジャマでコンビニ、独り言、小さな失敗をわざと見せる
3. **拒絶** — 例: 店員に小さなお願いをする、断られてもいい誘いをする
4. **不確実さ（コントロール）** — 例: 行き先を決めずに散歩、調べずに店に入る
5. **つながり（自己開示）** — 例: 親しい人に小さな本音を話す、小さな頼みごとをする

各段のテキストと難易度は実装時に別ファイル（`data/theme-templates.ts` 想定）へ具体的に書き出す。

## 8. 恐怖チェック（14問）

パレオな男のブログの「心理恐怖尺度」を意味を変えずに日本語で書き直したもの（ブログ文の丸写しはしない）。5分類の集計（失敗=1-3問目、拒絶=4-6問目、コントロール=7-9問目、つながり=10-12問目、評判=13-14問目）を行い、割合が最も高い分類をハイライトする。結果画面から、対応するテーマ未作成なら「作る」導線を出す。

再受検の促しはMVPでは実装しない（結果はいつでも `恐怖チェック` タブから再受検可能。履歴として複数回分 `fearChecks` に保存し、前回との差分は表示する）。

### 実装済み: 自由記述の実践記録・段階の後戻り・メモ欄・書き出し/読み込み（2026-09-15）

「急遽社内会議のリーダーを任された」のような予定外の出来事を自由記述で記録したい、という要望（本人が実際に使ってみて欲しくなった）を受けて実装。

- `PracticeRecord` に `stageId: string | null`・`freeText: string | null`・`memo: string | null` を追加
- `stageId` が `null` のときは `freeText` を使う自由記述の記録（`/themes/[id]/practice/freeform`）。テーマ単位にぶら下げる（テーマ横断の「その他」は作らなかった）
- `isThemeUnlocked`（ガードレール解放判定）は自由記述の記録（`stageId === null`）を除外して判定する。`meetsClearRequirement` はもともと特定の `stageId` で絞るので自然に除外される
- 振り返り画面の「累計回数」「不安スコアの合計低下」には自由記述の記録も含める
- 段階表画面に「◀ 無理をしていたら、前の段に戻る」を追加（`lib/progression.ts` の `retreatOneStage`）。いまの段を `todo` に、1つ前の段を `now` に戻す。先頭の段のときは表示しない
- 実践記録（段階表つき）にメモ欄（任意）を復活
- 設定画面に「データの書き出し・読み込み」を追加（`lib/backup.ts`）。書き出しはJSONファイルのダウンロード、読み込みは選んだファイルで**全データを上書き**（確認ダイアログを挟む）

### 実装済み: 段ごとの課題バリエーション（2026-09-15）

「挑む対象が段に1つしかなく、自由度がない」という指摘（本人）を受けて実装。段（Stage）1つにつき、実践のときに選べる課題を**最大3件・自由に編集**できるようにした。

- `Stage` に `tasks: string[]` を追加（`name` は段階表に出す代表的な課題名としてそのまま残す）
- 同梱テーマは `tasks: [元の課題名, '', '']` で作成される。残り2枠は自分で自由に追加する前提
- `lib/tasks.ts`: `padTasks`（3枠にそろえる）／`getTaskOptions`（空欄を除いた実際に選べる課題。1件も無ければ `name` にフォールバック。`tasks` が無い古いデータにも対応）
- 段階表画面（`/themes/[id]/ladder`）: 各段をタップで展開し、`TaskEditor`（`components/TaskEditor.tsx`）で3つの課題を自由に編集・保存できる。**現在挑戦中の段に限らず、すべての段で編集可能**
- 実践記録画面（`/themes/[id]/practice`）: `now` 段の `getTaskOptions` を選択式で表示し、選んだ課題名を `PracticeRecord.freeText` に保存する（段階表つきの記録でも freeText を使うようにした。もともと自由記述の記録専用だったが、「どの言い回しで挑んだか」を残す用途にも流用）

### 実装済み: 振り返り画面の成長の森（2026-09-17）

課題バリエーションを実際に使ってみた本人から、「何をやったか忘れてしまう」「今日頑張った分どれくらい成長したか見えると面白い」という要望（Duolingoの成長表現を参考にしたいとの指定）を受けて実装。姉妹アプリ「目標設定コーチ」（`product/prototypeManagementTool`）の森の成長表現（`src/lib/forest.ts` / `forest-draw.ts`）を調査し、同等の本格的な描画を移植する形で作った（本人の選択: 「prototypeManagementTool相当の本格的な森の描画」「成長表現から」着手）。

- テーマ1つ＝木1本、段＝小枝。小枝の状態は段の `status`（`todo`→蕾／`now`→葉／`clear`→花）に対応する
- 木の大きさ（`growth`）はそのテーマの実践回数に応じて単調増加（40回でフルサイズ、上限あり）。葉の量・色（`vigor`）は段のクリア率に応じて単調増加。**どちらも記録が増えない日があっても下がらない**（元アプリの「枯れて見せない」設計思想を踏襲）
- 全段クリアで実（フルーツ）が3つなる
- 「今回はここでよかった」を選んだ回数ぶん、木のまわりに落ち葉を配置（失敗ではなく積み重ねとして表現。５で導入した3択の「進まない」選択を、ここでも責めない見た目にする）
- `lib/growth.ts`（データモデル、`buildGrowth`）／`lib/growth-draw.ts`（`prototypeManagementTool`の幾何計算を土台にした純粋関数、SVGパスを計算するだけでReactに依存しない）／`components/GrowthForest.tsx`（SVG描画）。振り返り画面（`/review`）の最上部に表示
- 元アプリにあった「根・価値ノード」のサブシステムは実装コストを抑えるため今回はスコープ外にした
- 色はコーラル×クリームの本アプリの配色に合わせ、元の緑一色から秋の実り寄りの暖色（HSL計算を調整）に変更。乱数の種はテーマ・段のidから決めるため、開くたびに枝ぶりが変わらない（自分の木として覚えられるように）

**次フェーズ送り**: 何をやったか振り返るための履歴・ジャーナル画面（本人の要望のもう半分。「成長表現から」の指定により今回は後回し）

### 実装済み: 段のタイトルを課題1と連動させる（2026-09-22）

「段のタイトルだけ編集できないのは使い勝手が悪い。課題1自体がタイトルと連動してほしい」という指摘（本人）を受けて変更。自作テーマの段名は長いテーマ名の繰り返し（例:「女性を自然にナンパして仲良くなるを頭の中で思い描く」）になりがちで、直す手段が無かった。

- `lib/tasks.ts` に `getStageTitle(stage)` を追加。**課題1（空欄なら次に書いてある課題）をそのままタイトルにする**。どの課題も空欄なら、もとの `stage.name` を残す（本人の指示「なければ既存の文章で大丈夫」）
- 段名を出すすべての場所で使う: ホームの「いま:」／段階表／テーマ詳細／プランの段選択／成長の森の小枝／後戻りの確認文
- 段名を編集する専用UIは作らない。**課題1を書き換える＝タイトルを書き換える**にそろえるのがこの変更の趣旨。`TaskEditor` の課題1の枠にその旨を書き、保存時に `stage.name` も課題1にそろえる（書き出したデータ側もズレないように）
- 既存データは移行不要。課題1を書いてある段はその文言に、書いていない段は元の名前のまま表示される

### 実装済み: イフゼンプラン画面（2026-09-22）

「暴露療法を習慣にしたい。クリアしたい段の課題を、日常のどの場面で使うかを管理する画面が欲しい」という要望（本人）を受けて実装。3.の工夫1（if-thenプランニング）は、それまで**テーマに1つだけ**（`Theme.ifThen`）で、どの段の課題かとも紐づいていなかったため、専用画面として作り直した。

本人の選択: 「やること」は**段の課題から選ぶ**／一覧は**場面・時間帯でまとめる**。

- 下部バーに6つ目「プラン」を追加（段階表といどむの間。ご指定の位置）。テーマをまたいだ全プランを `/plans` の1画面で見る
- 1プラン = `{ themeId, stageId, slot, trigger（場面）, action（やること）, active }`。localStorageキー `exposure.plans`
- 時間帯（`slot`）は 朝／通勤・移動／仕事中／帰宅後・夜／いつでも の5つ。この順に見出しでまとめ、空のグループは出さない。1日の流れで自分の暴露を見渡せるようにするため
- 「やること」はテーマ→段を選ぶと、その段の課題（最大3件）から選べる。段を選んだ時点で1件目を初期値に入れる（自由入力で書き換え可）。段に紐づけない自由なプランも作れる
- プランの「やった」→ `/themes/[id]/practice?planId=...` へ直行し、記録に `PracticeRecord.planId` を残す。これで各プランに「この場面で◯回できた」を表示できる（減らない積み上げの数字。既存方針と同じ）
- 今はやらないプランは消さずに「お休み」にできる（`active`）。テーマの非表示と同じ考え方
- 旧 `Theme.ifThen` はプラン画面を開いたときに一度だけプランへ移し、テーマ側は `null` にする（`migrateLegacyIfThen`）。二重管理を避けるため。テーマ詳細のカードは移行後のプランを読んで表示するだけにし、`components/IfThenEditor.tsx` は削除した

### 実装済み: テーマの追加・非表示・削除をホームに集約 ＋ 下部バーの固定（2026-09-22）

本人がスマホの本番で使って見つけた3点を修正した。

1. **「＋ 新しいテーマを追加」を押しても追加できない** — 押せない見出し（`div`）で、その下に出る候補は「まだ追加していない同梱テーマ」だけだった。同梱5テーマを全部追加済みだと候補が0件になり、見出しを押しても何も起きなかった。押せるボタンにして開閉式にし、**自分でテーマ名を決めて作る**入力欄を足した（`createCustomTheme`）。自作テーマは同梱テーマと同じく難易度1〜10の10段で作られ（2026-09-22修正。最初は1/4/7の3段しか作っておらず「一部しか出ない」と指摘された）、中の課題は既存の課題編集で自由に書き換える前提
2. **非表示・削除をホームに集約** — ホーム右上の「編集」で各テーマに「非表示にする」「削除する」が出る。非表示は段階表画面からも変わらず可能。削除はテーマとその実践記録を消し、元に戻せないので確認を挟み、文面で「非表示」を先に案内する。削除した同梱テーマは追加候補に戻る（テーマ名で判定しているため）
3. **スマホで下部バーが見えなくなる** — `min-h-screen`（=`100vh`）がスマホのアドレスバーの裏まで含むため、流れの中に置いた下部バーが画面外に出ていた。`BottomNav` を `fixed` にして常に画面下端に出し、同じ高さの空き（スペーサー）を流れに残して最後の要素が隠れないようにした。`env(safe-area-inset-bottom)` ぶん背を高くしてホームバーとの重なりも避ける

`lib/themeVisibility.ts` は役割が増えたので `lib/themeAdmin.ts` に改名した（`setThemeHidden` / `splitByVisibility` / `removeTheme` / `removeThemeRecords` / `createCustomTheme`）。

### 実装済み: テーマの非表示（2026-09-20）

「今は気にしなくてよいテーマがホームに並んでいる」という指摘（本人）を受けて実装。最初は「削除」と依頼されたが、本人の意図は「今は見なくてよい」なので、**記録を消さない非表示**にした。

- `Theme` に任意の `hidden?: boolean` を追加（無い古いデータは表示扱い）
- 段階表画面（`/themes/[id]/ladder`）の最下部「今は気にしなくてよいので、このテーマを非表示にする」→確認→ホームへ戻る
- ホーム下部の「非表示のテーマ（N）」を開くと「表示に戻す」で復元できる。非表示にしたテーマは「新しいテーマを追加」の候補にも再登場しない（テーマ名で判定しているため）
- 振り返りの「成長の森」と累計回数は、非表示のテーマも含めて数える（成長は減らさない方針を優先）
- `lib/themeVisibility.ts`（`setThemeHidden` / `splitByVisibility`）

## 10. 技術構成

- Next.js（App Router）+ TypeScript + Tailwind CSS（デザイントークンはモックの色をそのまま採用）
- 状態: localStorage を直接読み書きするカスタムフック（`useLocalStorageState` 的な薄いラッパー）。グローバル状態管理ライブラリは導入しない（YAGNI）
- ルーティング: `/`（テーマ一覧）, `/themes/[id]`（テーマ詳細）, `/themes/[id]/ladder`, `/themes/[id]/practice`, `/review`, `/fear-check`, `/fear-check/result`, `/settings`, `/onboarding`
- テストは、データ層（進級判定・ガードレール判定・恐怖チェック集計などの純粋関数）に Vitest でユニットテストを書く。UI コンポーネントの自動テストはMVPでは書かず、`webapp-testing` / ブラウザでの目視確認で代替する
